## Key finding: two different objects

- Display object (display.cpp, ctor 0x55ef50): your "screen manager". Areas/widgets live here. There are two, at scrman+0x3844 (0xb77c94) and scrman+0x132ea5 (0xca72f5).
- scrman object (scrman.cpp, global at 0xb74450): a screen STACK manager. 16 channels (one per player), each with a history of 0x30-byte records and a linked list of 0x300-byte screen nodes. Each record holds a Display pointer at record+0x28 (scrman+0x7fc for channel 0). Range B (0x7fdc00-0x802f80) is this object, not area/widget code.
- Source files: range A = display.cpp (asserts at 0x9c36ec) with network.h inline writers (string at 0x9c3734 is "network.h", not scrman). Range B = scrman.cpp (0xa7ddbc), confirmed by assert in 25 functions, other 24 by adjacency (no assert). scrman.cpp also extends outside B: 0x7fc380-0x7fdbff before and 0x803320+ (e.g. 0x803d80, 0x804030) after.

## Section 1. Call sequence of one small real element (0x49d930)

0x49d930 is the smallest function that calls both 0x55fba0 (area) and 0x55f990 (widget). It builds a one-line progress/status box. It is a helper, not a full screen. Stack args at entry: [esp+4].. (ret value 1; arg at [esp+0x18] = non-zero check, else error box). The Display is fetched as `[scrman_channel_record + 0xb74c4c]`, where record = 0xb74c24 + DAT_00b77c7a * 0x300 (record +0x28 = Display*).

1. `ecx=0xb74450 (scrman)`, call 0x804030 (12 args, ret 0x30; scrman.cpp area-rect helper, unknown detail). It returns an id in EAX. Used as owner_widget below.
2. `ecx = [DAT_00b77c7a*0x300 + 0xb74c4c]` (Display). Call 0x55fba0 (area) with 11 args, in order x1,y1,x2,y2 = 0,0,0,0; column_count 0; column_weights 0; row_count 0; row_weights 0; flags 0x130; colour = DAT_00ae31aa; owner_widget = result of step 1. Returns the area index; stored at [arg]. Then sets DAT_00adae0c = 1.
3. Call 0x4bffc0 (text formatter, unknown detail) into DAT_00de1f64. If the buffer is empty it copies a default string (0x990f4c).
4. Same Display in ECX. Call 0x55f990 (widget) with 18 args, in order: flags 2; x1,y1,x2,y2,column,row all 0; style 0x10; colour DAT_00ae31aa; highlight DAT_00aebdec; text_flags 1; font 1; text colour DAT_00aebdea; text ptr 0xde1f64; +0x40 = 0; +0x08 = 5; +0x48 = pointer computed from arg; area index = the value from step 2.

Each real screen has three parts. The screen is pushed with 0x7fe600 (build_fn, input_fn, flag, leave_fn, extra) from one of 181 call sites. The build_fn runs inside 0x7fdc00 or 0x7fc7e0 after 0x55f7c0(1) resets the Display. The build_fn calls 0x55fba0 and 0x55f990 many times, sets string slots with 0x7ff270, and the loop then calls 0x55f300 to draw. The input_fn (node +8) receives the clicked widget index from 0x55f620 and returns -0xb to end the screen or -9 to pop it. I read this from the 0x7fdc00 decompile. I did not trace a complete screen build_fn end to end. See doubts.
